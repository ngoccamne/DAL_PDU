Current firmware architecture

This is the short overview of the DAL_PDU firmware. The detail lives in two pages:

  • Code architecture: layers, dependencies, data flows, task inventory, shared state.
  • Scheduler design: the task model, API, timing, concurrency rules, and limits.

Target and entry point

The Atmel Studio project is PDU/firmware/DAL_PDU/DAL_PDU/ and targets the ATmega128A at 12 MHz. main.c calls APP_Main() in src/dev/M0_App/app_main.c, which initializes everything and then runs the main loop, which only dispatches SCH_HandleScheduledTask(). Modbus runs as a 5 ms task.

Layers

Layer Responsibility
M0_App Startup, console, heartbeat LED, TRANS and fault handling, rail monitoring, watchdog supervision, Modbus callbacks.
M1_Sys Scheduler (1 ms tick and task dispatch), CommandLine (parser and handlers), SystemData (shared status).
M2_BSP Board pin map, UART ownership, timer ISR, I2C, power GPIO, watchdog, Modbus port, chip bindings.
M3_Driver Component drivers (UART, software UART, I2C, GPIO) and chip drivers (TPS55287, PAC1934, 24C04).
M4_MiddleWare Byte FIFO, printf hook, FreeMODBUS (submodule).

Scheduled work

Seven tasks run from the main loop, driven by a 1 ms Timer0 tick: console (10 ms), heartbeat (20 ms), TRANS fault check (6 ms), Modbus (5 ms), rail monitor (1000 ms), watchdog (10 ms), and board temperature (1000 ms). The full inventory, with phases and what each task reads and writes, is in Code architecture §4.

Interfaces

  • UART0 (PE0/PE1) and the software console (PE3/PE4) both run at 9600 baud and share one command table. Each port has its own line buffer, and replies go back to the port that sent the command. See Current command reference.
  • Modbus RTU runs as the configured slave (default 1) at the configured baud (default 9600) on USART1 (PD2/PD3, RS485 direction on PD5). See Modbus RTU implementation.
  • I2C on PD0/PD1 serves the TPS55287 (VOUT), the PAC1934 monitor, and the 24C04 EEPROM.

Power path

TRANS is switched by the active-low PC2 eFuse. VOUT is enabled only while TRANS is on and both fault inputs are clear. A fault turns VOUT off first, then TRANS. The fault stays latched in internal EEPROM until it is cleared by command. The PAC1934 task records voltage, current, and power for VOUT, +12, +5_TRANS, and +5, but it does not yet enforce setpoint agreement or overcurrent limits.

The mode (NORMAL, MANUAL, WARNING, or ERROR) gates TRANS. A missing regulator, or a limit trip in NORMAL, is ERROR. An unreadable PAC1934 or a latched fault is WARNING. Running drops outputs to off after 5 seconds without a Modbus request. See Mode state machine.

Build and tests

Open DAL_PDU.atsln in Atmel Studio 7 for the AVR build. From SOFTWARE, run make -C PDU/tests test for the host unit tests. Host tests do not replace bench checks of serial timing, output voltage, or fault wiring.
