Current text command reference

The same case-sensitive commands run on UART0 and the software UART console at 9600 baud. Terminate a line with CR, LF, or CRLF; arguments are separated by spaces. Both ports echo input, begin with a > prompt, and send the reply to the port that received the command. The tables show reply text only, without echo or prompt.

General and application commands

Command example Expected reply Notes
help Starts with Available commands and ------------------, followed by all command help lines Entries are sent as the 256-byte response buffer drains.
version DAL_PDU firmware v0.1.0 (Development) build c7f0bf8-dirty Firmware version and build. The build is the short git commit. -dirty means the tree had uncommitted changes when it was built.
led get LED on=1000 ms off=1000 ms Default after reset.
led set 250 750 LED on=250 ms off=750 ms Both decimal durations must be nonzero, at most 4294967295 ms.
trans get TRANS off Adds fault if either eFuse fault input is active.
trans on TRANS on If a fault is latched, the reply is TRANS fault and PC2 stays disabled. A live-but-not-yet-latched fault does not refuse this reply by itself (decided 2026-10-15, see Mode state machine §4); the 6 ms poll still catches it, latches it, and disables PC2 within one cycle regardless.
trans off TRANS off Requests TPS55287 VOUT off before disabling TRANS. With an active fault, reply is TRANS off fault.

I2C maintenance commands

Addresses are 7-bit (0x08–0x77); register and data bytes are 0x00–0xff. Numbers accept decimal or a 0x hexadecimal prefix. The examples below assume one responding TPS55287 at address 0x75 and its reset register values.

Command example Expected reply Notes
i2cdetect 0x74 0x75 0x75 Scan inclusive range; the trailing space precedes CRLF. With no devices, the reply is an empty line. Plain i2cdetect scans 0x08–0x77.
i2cget 0x75 0x04 0x03 Reads one register byte using a repeated START. Without a register, reads one byte directly.
i2cset 0x75 0x04 0x03 I2C write OK Writes one register byte. This example preserves the TPS55287 reset feedback setting; raw writes can change power configuration.

An unresponsive address returns I2C error for i2cget or i2cset.

24C04 EEPROM commands

U14 has 512 bytes at logical addresses 0 through 511. Numbers accept decimal or 0x hexadecimal notation. The examples assume a connected chip and successful I2C transfers.

Command example Expected reply Notes
eeprom probe EEPROM present Reports EEPROM unavailable if the chip does not acknowledge.
eeprom read 0x100 4 EEPROM 0x0100: de ad be ef Example assumes those four bytes were stored. Omitting the length reads one byte; length must be 1–16.
eeprom write 0x100 deadbeef EEPROM write OK Writes four bytes and verifies them by reading back. The hex string must have 2–32 digits (1–16 bytes); an optional 0x prefix is accepted.

Writes lower the PA0 write-protect pin only during the operation. The reply is EEPROM read failed or EEPROM write failed if the I2C transfer or verification fails. Out-of-range addresses, reads or writes past byte 511, and malformed hex data return Invalid argument.

TPS55287 output commands

U5 is detected at 0x74 or 0x75 according to its MODE pin. The examples assume 0x75 and no active faults. tps55287 set and tps55287 on power TRANS on first if it is off, and confirm the chip answers, instead of requiring a separate trans on beforehand. tps55287 off never powers TRANS on just to turn itself off.

This board wires an external feedback divider (R22 = 102 kΩ, R30 = 11.3 kΩ to GND; ratio ≈ 0.0997), not the chip's internal ratio. The TPS55287 resets to internal feedback (register 0x04 = 0x03) every time its EN/UVLO drops — including every time TRANS is power-cycled, since TRANS is off whenever VOUT is idle. So every successful TRANS power-up (trans on, tps55287 set/on, or the equivalent Modbus write) also writes register 0x04 to 0x80 (external feedback) and reads it back to confirm. Every setpoint write and output-enable request checks that configuration again. If a raw I2C command changed it while VOUT was on, firmware disables VOUT before correcting feedback and re-enables it only after a successful setpoint write. tps55287 status's internal-feedback/external-feedback text reflects whichever the chip is actually reporting at that moment.

Command example Expected reply Notes
tps55287 status TPS55287 addr=0x75 off external-feedback Appends SCP, OCP, or OVP for set protection flags. Reading status clears those latched flags. Does not power TRANS on; fails if TRANS is off.
tps55287 set 5000 TPS55287 set OK Powers TRANS on first if it is off (which also re-asserts external feedback). Sets a nominal 5000 mV request against the external ratio. The actual output has not been measured by this command.
tps55287 get VOUT setpoint 5002 mV Converted back from the stored reference code using whichever feedback mode and ratio the chip currently reports; register conversion may differ slightly from the requested millivolts. Does not power TRANS on; fails if TRANS is off.
tps55287 on TPS55287 on Powers TRANS on first if it is off. Refused if a PC4/PC0 fault is latched, TRANS ends up off, the chip does not respond, or external feedback cannot be re-asserted. A live-but-not-yet-latched fault does not refuse this by itself; the 6 ms poll still catches and latches it shortly after.
tps55287 off TPS55287 off Clears the chip's output-enable bit. Never powers TRANS on.

tps55287 set and tps55287 on report TPS55287 set failed (TRANS) / TPS55287 enable failed (TRANS) if TRANS was off and powering it on failed (fault active, latched, the regulator did not respond, or external feedback could not be re-asserted — see Mode state machine). With TRANS already on, tps55287 set rejects values below 800 mV and above ~12 V (the external ratio's range), reporting TPS55287 set failed (I2C or range) for an I2C failure or an out-of-range request. tps55287 on reports TPS55287 enable failed (I2C or TRANS interlock) if TRANS is faulted or I2C fails after TRANS is already on. A failed get or status reports TPS55287 read failed (I2C).

PAC1934 rail monitor

The one-second background task reads U10 through the shared I2C bus. The board uses 10 mΩ shunts on all four channels. The example below assumes the device was detected at 0x1f and all channels measure 5 V, 1 A, and 5 W.

Command example Expected reply Notes
pac1934 get PAC1934 addr=0x1f followed by VOUT 5000 mV 1000 mA 5000 mW, +12 ..., +5_TRANS ..., and +5 ... Shows the latest cached sample; plain pac1934 and pac1934 status are aliases.
pac1934 refresh Same format as get Takes a new measurement immediately; normal polling remains every 1000 ms.

Before the first successful poll, or after a failed I2C read, the reply is PAC1934 unavailable. Rail labels follow channel order 1–4 in the board design; confirm the physical wiring and installed 10 mΩ shunts during bring-up; the hardware review found a shunt-value mismatch in the BOM.

Board temperature

The one-second temperature task samples the TC1047A on the TEMP net (PF1/ADC1), averaging 16 conversions. The reply is in degrees Celsius with one decimal place.

Command example Expected reply Notes
temp TEMP 25.1 C Shows the latest cached sample. temp get is an alias.
temp refresh TEMP -0.2 C Takes a new sample immediately; normal sampling remains every 1000 ms.

If the ADC fails or the reading is outside the TC1047A range of −40 °C to +125 °C, the reply is TEMP unavailable. The same value is available over Modbus as input register 30021.

Operating mode

The mode is NORMAL, MANUAL, WARNING, or ERROR. See Mode state machine.

Command example Expected reply Notes
mode MODE normal and CAUSES regulator=0 pac1934=0 eeprom=0 latch=0 limit=0 setpoint=0 bus=0 link=0 mode get is the same. A 1 in CAUSES means that cause is active. link is Modbus link loss (no valid request for the configured timeout, default 5 s); it only raises WARNING and does not turn TRANS/VOUT off by itself.
mode manual MODE manual Takes operator control even when an ERROR cause is set. A confirmed eFuse fault remains latched and reported, but software does not turn VOUT or TRANS off in MANUAL.
mode normal MODE normal Checks the regulator and limits if either has raised ERROR, clears healthy causes, then leaves MANUAL. Refused with MODE refused: error while a cause remains or an eFuse fault is latched.

Fault latch

A fault that switches TRANS off is latched in the ATmega128A internal EEPROM, so it survives a reset. While any bit is latched, trans on is refused and VOUT cannot be enabled. The same latch is available over Modbus coil 00003.

Command example Expected reply Notes
fault get FAULT latch pc4=0 pc0=0 active pc4=0 pc0=0 latch shows the stored bits. active shows the live eFuse inputs. pc4 is the 12V TRANS fault and pc0 is the 12V_MCU fault. Each is latched, and clears only when its input is inactive.
fault clear FAULT latch cleared Clears the latch only. Refused with FAULT clear refused: fault still active while a fault input is active. TRANS stays off, and can be enabled again only when no fault input is active.

A damaged EEPROM record is treated as both faults latched, so the unit stays off until the latch is cleared.

Limits and events

Over-temperature and overcurrent are checked every second in every mode. In NORMAL, a trip turns VOUT and TRANS off and sets the limit ERROR. In every mode, each trip is logged once as a WARNING event in the 24C04. mode normal clears the limit ERROR once the regulator responds and limits are back in range. The ERROR is stored in internal EEPROM, so it survives a reset until that check succeeds.

Command example Expected reply Notes
limit LIMIT temp=850 vout=1000 trans=1000 limit get is the same. Temperature is in tenths of a degree C, so 850 is 85.0 C. Currents are in mA.
limit temp 900 LIMIT temp=900 vout=1000 trans=1000 Range -400 to 1250. Stored in internal EEPROM and used at the next check.
limit vout 3500 LIMIT temp=900 vout=3500 trans=1000 Range 100 to 5000 mA. limit trans sets the +5_TRANS limit the same way.
limit vout 70000 LIMIT refused: out of range Nothing changes.
event get EVENT seq=1 sev=WARNING code=TEMP mode=NORMAL value=900 time=unset source=UNSET Lists the 24C04 ring, 32 slots. Codes are TEMP, VOUT_CURRENT, TRANS_CURRENT, CONFIG_CHANGED, SETPOINT_MISMATCH, and CLOCK_SET. Value is tenths of a degree C, mA, or mV, as the code says. time is UTC (YYYY-MM-DDTHH:MM:SSZ), or unset. source is where that time came from: UNSET, RESTORED, or SET. EVENT none when empty.

Configuration

The Modbus slave address and baud rate are read at boot. Modbus 40105 and 40106 show the active values. The communications timeout takes effect at once. Each change is logged once as an INFO event (CONFIG_CHANGED).

Command example Expected reply Notes
config CONFIG address=1 baud=9600 timeout=5 source=DEFAULT config get is the same. source=DEFAULT means no valid record is stored, so the compiled defaults are in use. source=EEPROM means the stored record is in use.
config set address 7 CONFIG address=7 baud=9600 timeout=5 source=EEPROM, then Address and baud take effect after reboot Range 1 to 247. Takes effect at the next boot.
config set baud 19200 CONFIG address=7 baud=19200 timeout=5 source=EEPROM, then the reboot line Supported: 1200, 2400, 4800, 9600, 19200, 38400. Takes effect at the next boot.
config set timeout 10 CONFIG address=7 baud=19200 timeout=10 source=EEPROM Range 1 to 60 s, default 5. Outputs turn off after this long without a valid Modbus request. Takes effect at once.
config set address 0 CONFIG refused: out of range Nothing changes.
config set baud 115200 CONFIG refused: unsupported baud Nothing changes.
config_reset confirm CONFIG reset to defaults, the CONFIG line, LIMIT temp=850 vout=1000 trans=1000 Restores the configuration and the limits to the defaults and stores them. The reboot line appears only if the address or baud changed.
config_reset Invalid argument reply Without confirm nothing changes.

config_reset does not clear the event log, the boot history, the fault latch, or a limit ERROR. A healthy mode normal request clears a limit ERROR.

Input errors

The console prints Unknown command, Too few arguments, Too many arguments, or Invalid argument for parser/handler errors. For example, led set 0 500 returns Invalid argument. Input lines longer than 63 characters return Line too long. A command response that fills the shared output buffer ends with [output truncated].

The larger proposed command set and power/telemetry requirements remain in Use cases, user stories & commands. The currently implemented Modbus register map is separate from these text commands.

Telemetry

Command example Expected reply Notes
telemetry SETPOINT 5000 mV, then one line per rail SETPOINT unset until a setpoint is commanded since reset. Each rail line is VOUT, +12, +5_TRANS, or +5 with measured mV, mA, and mW. PAC1934 unavailable when the monitor cannot be read.

Setpoint

setpoint get reports the commanded VOUT setpoint held in system data. It is the value last set by the console or by Modbus 40001, and it does not read the chip. tps55287 get still reads the TPS55287 register.

Command example Expected reply Notes
setpoint get SETPOINT 5000 mV SETPOINT unset until a setpoint is commanded since reset.

Boot information

Each boot adds one to the boot count, which is kept in internal EEPROM. The cause comes from the reset flags read at startup. A watchdog fault is recorded before the TPL5010 resets the unit, and it is written to the boot record at the next boot.

Command example Expected reply Notes
bootinfo BOOT count=2 cause=CLIENT_WATCHDOG source=MODBUS bootinfo get is the same. Causes are POWER_ON, BROWN_OUT, EXTERNAL, AVR_WATCHDOG, CLIENT_WATCHDOG, COMMAND (from reset confirm), and UNKNOWN. Sources are CONSOLE, HEARTBEAT, MODBUS, POWER_MONITOR, TEMPERATURE, and MONITOR. source=- unless the cause is CLIENT_WATCHDOG.

bootinfo history lists the last 10 boots, newest first, from internal EEPROM.

The same boot count, cause, and source are on Modbus input registers 30032–30034.

Clock

A software clock keeps UTC from the last set and the scheduler tick. It has no battery. Every 15 minutes, and on each set, it stores a checkpoint in internal EEPROM. After a reset it restores the last checkpoint with source RESTORED, which is approximate, since the power-off time is unknown. A set from the console or Modbus gives source SET. Without a checkpoint the clock is UNSET. Events carry the clock time and its source.

Command example Expected reply Notes
time TIME 2026-10-06T12:34:56Z source=SET or TIME unset source=UNSET time get is the same. UTC. The source is UNSET, RESTORED, or SET.
time set 1791290096 TIME 2026-10-06T12:34:56Z source=SET Sets the clock from Unix seconds. Logged as a CLOCK_SET event.
time set 4294967295 TIME refused: reserved value The value means unset. Nothing changes.
time set 17x Invalid argument reply Nothing changes.

The clock uses the MCU clock. It has no temperature compensation, so it drifts with the crystal. The OBC should set it periodically. Modbus reads and sets the same clock: 40040–40041 to set and read, and 30039–30040 to read.

Status and reset

Command example Expected reply Notes
status STATUS, then the replies of mode, temp, telemetry, fault get, and bootinfo, one after another Read-only summary for the technician. Each section has the same format as its own command.
reset confirm RESET outputs off, restarting Turns VOUT and TRANS off, sends the reply, then restarts the MCU through the watchdog after about 0.1 s. The next boot reports cause=COMMAND. Without confirm nothing happens.
reset Invalid argument reply Needs confirm.
persist_reset internal confirm PERSIST_RESET internal EEPROM erased, restarting Turns VOUT and TRANS off, blanks every byte of internal EEPROM (fault latch, limit error, limit values, boot record and history, config, clock checkpoint), then restarts the same way reset confirm does, since all of that is cached in RAM at boot and needs a fresh init to pick up the now-blank EEPROM. Blanking takes under a second on a lightly-used chip (it skips bytes that already read 0xFF), well inside the TPL5010's 10 s window.
persist_reset external confirm PERSIST_RESET external EEPROM erased Blanks the whole U14 24C04 (the event log ring). Nothing is cached from it at boot, so this does not restart the MCU or touch the outputs. A failed erase (chip not acknowledging) replies PERSIST_RESET external EEPROM failed.
persist_reset internal, persist_reset external, persist_reset Invalid or too-few-arguments reply Each needs its scope (internal or external) and confirm.

persist_reset is the only command that returns EEPROM to the state of a never-written chip; fault clear, mode normal, and config_reset confirm each clear a narrower, specific piece of internal EEPROM state (see Mode state machine §8 and the configuration section above).
